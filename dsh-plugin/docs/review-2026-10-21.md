## 三、发现的问题

### P1 会话级「结合上下文」选择不跨刷新（本轮修复）

**证据**：`src/client/tier-store.ts` 的 `tierOverrides` / `contextOverrides` 是模块级 `Map`，`selectUseContext` 只写内存（原 :84-87）。客户端 bundle 每次刷新页面都会重新执行，`Map` 随之清空 → 回到档位预设（标准档 = 开）。装插件、改配置、任何一次刷新都会「把用户改成不结合上下文的勾又勾回来」。
**判断依据**：这正是用户报告的「上次改了不结合上下文，现在又变回去了」；且与 R7 的撤销「只存在于当前页面内存」不同，用户对开关的预期是**记住**，不是**一次生效**。
**二次根因（补）**：只把状态存起来还不够——会话键本身在漂移。`props.sessionId` 在 dsh 0.1.2-rc 起已从输入槽标准 props 里移除，`session-key.ts` 会退化成「按 `inputActions` 现场铸一个 `pe:zone:N`」，而它每次刷新都变，于是存下的键永远匹配不回来。修法是同时读 composer 的 owner share `session.sessionId`（`InputZone.session: ConversationSnapshot`，渲染点 `renderSlot("conversation.input.right", zone)`），有真 id 才用它做键。
**修法**：两层分开存——持久默认进 `localStorage`（键 `…:default-tier:v1`，跨重启），会话临时选择进 `sessionStorage`（键 `…:session-picks:v1`，刷新存活、关 DSH 即失效，最多 64 个会话）。存储不可用（隐私模式、被策略挡、配额满）时静默退回内存，不阻断输入框。
**不选的方案**：把开关直接写进宿主 `contextAware` 总开关——那样「关一次」会让全局读历史永久失效，且胶囊上的勾选会变成禁用态，语义比现在更糟。

### P2 系统档可被设为默认档，与热键层规则分叉（本轮修复）

**证据**：`src/client/TierMenu.tsx` 的 `pinDefault` 只看 `canPersistTier()`，不判档位；而热键层 `enhance_hotkey.py` 的 `set_default_tier` 明确 `raise ValueError("默认档只能是基础、标准或专业")`。
**判断依据**：同一套规则在两个入口给出相反的答案，用户换入口就会踩坑；且系统档是八段人设，做默认会把每次增强（含热键与 `/enhance`）都变成人设重写。
**修法（本版改为行尾单选）**：「临时」和「默认」不再是两个动作的两个按钮，而是同一行的两件事——点整行＝只在本会话用，勾该行右端的单选＝设为默认。系统档的单选 `disabled`，行标题给出说明 `tier.menu.default.systemBlocked`；没有绑定 settings 写手时单选仍然可用（本地默认照存，只是宿主那份 `defaultTier` 落后）。

### P3 `[ITERATE]` 段未进插件生成物（已知差异，建议保留并文档化）

**证据**：`scripts/generate-tiers.mjs` 只产出 `COMMON/BASE/STANDARD/PROFESSIONAL/SYSTEM`；`grep -r "@iter\|ITERATE" src/` 在插件里零命中；热键层有 `ITER_BLOCK = re.compile(r"(?ms)^[ \t]*@iter\s*[:：]…")` 与「≤1.25 倍」约束。
**判断依据**：不是缺陷而是取舍——插件的迭代方式是「对输入框里已是上一版的文本再点一次」，天然带上下文；补 `@iter:` 解析会引入「元指令不入正文」这一整条护栏，收益不抵成本。
**建议**：在 README 明确写「插件不实现 `@iter:`，重复点击即迭代」，避免以后被当成 bug。

### P4 设置文档落点未证实（开放项，需实测）

**证据**：在 `DSH_HOME`（`E:\aaaWorkspace\WorkSpace\dsh\.dsh`）、`~/.dsh`、`%APPDATA%` 下 grep `prompt-enhance` / `defaultTier` / `contextAware`，**找不到任何含插件命名空间的设置文档**（命中项全是会话缓存里的对话正文）。`profiles/desktop/cordis.patch.yml` 里也没有 `prompt-enhance` 条目。
**判断依据**：若设置不落盘，「设为默认档」同样不跨重启——那是一条会静默丢写入的承诺。当前无法从磁盘证伪，只标注为未验证，不臆断。
**实测配方**（30 秒）：胶囊里点「专业」那一行**右端的单选**（＝设为默认）→ 重启 DSH → 看胶囊是否仍显示「专」；再跑一次增强，宿主日志 `[prompt-enhance] <id> tier=…` 会打出实际档位。`localStorage` 的 `dsh-prompt-enhance:default-tier:v1` 是本地权威副本，所以即使宿主那份没落盘，重启后胶囊也会回到「专」。

### P6 上下文圆点的语义与文案都在说谎（本轮修复）

**证据**：`src/client/TierMenu.tsx` 里圆点用 `contextIsPinned = pinnedContext !== undefined` 判定，即「存在默认就点亮」，与档位行「这一行就是默认」的语义不一致；title 又用 `useContext`（本会话实际值）去渲染 `tier.menu.context.pinned`，于是默认固定成「开」、用户临时拨成「关」之后，提示会写「已固定默认：关」。同时 `contextIsOverridden` 算了却从未渲染，用户看不到「默认是开、你现在是临时覆盖」这句话。
**判断依据**：用户实测「切换了结合上下文，默认按钮是不变了，那我是不是切换之后默认的也跟着改变了」——UI 无法回答这个问题就是缺陷。且圆点与档位行的同形控件给出不同含义，属前后不一致。
**修法**：圆点改判 `contextIsDefault = useContext === defaultContext`（新增 `tier-store.ts` 的 `effectiveDefaultContext(tier)`：已存默认优先，否则该档预设），语义与档位行统一为「你看到的就是默认」；`makeDefaultContext(next)` 只在当前态 ≠ 已存默认时写入、相同则取消固定，且不再顺手写本会话选择；title 分三档文案（可固定/已固定/被临时覆盖），弹层底部在「行可用且当前态 ≠ 默认」时多渲一行 `role="status"` 说明覆盖关系。翻方框仍只写 `sessionStorage`，绝不碰默认。

## 四、优化后的完整方案（结构不变，只修上述偏差）

1. **入口**：插件提供 `conversation.input.right` 的一颗胶囊 + ✨；热键 `ctrl+shift+alt+a` 走同一条 `runEnhance`；`/enhance` 兜底。
2. **档位**：四档，规则唯一真源 `core/rules.md`，构建期生成，`--check` 失败即构建失败。基础档走宿主本地确定性整理（零模型调用），其余三档走模型。
3. **两层状态**（临时层跨刷新存活，默认层跨重启存活）：
   - 持久默认：`localStorage …:default-tier:v1`（本地权威）+ `settings.defaultTier`（宿主副本）+ `contextAware`（总开关）；
   - 会话临时：`sessionStorage …:session-picks:v1`，点整行即选中，刷新后仍在、关 DSH 即释放；
   - 优先级：总开关 off → 一律无上下文；档位不许 → 一律无上下文；会话覆盖 → 该值；否则档位预设。
   - 会话键必须用宿主真 id（`InputZone.session.sessionId`），不能用每次刷新都变的兜底键。
4. **上下文**：基础永不带；标准 4 条 / 3000 字；专业与系统 12 条 / 6000 字；与 `contextMaxMessages` / `contextMaxChars` 取较小值。
5. **交付形态**：基础 / 标准 / 专业直填（一次性请求 → 整段替换 → 撤销条）；系统档开面板（流式、并排对比、显式回填）。
6. **反馈与撤销**：转动的圆环 + dock 行秒数与取消；`Ctrl+Z` 仅在草稿仍是增强文本时接管；失败走同一行内联提示，输入框不被写过就不需要回滚。
7. **默认档**：每行右端一颗圆点＝把当前这一行设为默认档；整行点击＝本会话临时档。仅基础 / 标准 / 专业可选，系统档圆点禁用并给出说明。
8. **上下文默认**：同一行右侧的圆点语义统一为「你看到的就是默认」——勾着＝当前状态已经是默认，翻动方框立刻变空，只有点圆点才把当前状态写成默认；点在同状态上则取消固定、回到档位预设。翻方框永远只写本会话，不碰默认（见 P6）。
