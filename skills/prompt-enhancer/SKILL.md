# 提示词增强器

把“人话草稿”变成“可直接发给 AI 的提示词”：只改写法，不改意图。

**唯一规则真源**：`references/rules.md`（仓库内是根目录 `core/rules.md` 的同步副本）。入口层只补充调用解析、取材差异与交付方式；保真底线、输出纪律、用户/系统两种写法与迭代规则均以内核为准。

## 调用解析

- `$p <草稿>` / `$prompt-enhancer <草稿>`：其后全部文本 = 草稿，按当前默认档增强；初始默认是**标准档**。
- `$p base <草稿>` / `$p 基础 <草稿>`：基础整理，只轻度理顺文字、补标点和分段。
- `$p standard <草稿>` / `$p 标准 <草稿>`：标准增强，默认中间档，输出一段自然段提示词。
- `$p pro <草稿>` / `$p 专业 <草稿>`：专业增强，输出五段结构化提示词；仍是提示词本体，不是执行报告。
- `$p user <草稿>` / `$p 用户 <草稿>`：强制按用户提示词增强。
- `$p system <草稿>` / `$p 系统 <草稿>`：强制按系统提示词增强。
- `$p 默认 <档位>` / `$p default <tier>`：持久切换默认档，只接受 `基础/base`、`标准/standard`、`专业/professional`。
- `$p 切换默认 <档位>`：与 `$p 默认 <档位>` 等价；热键侧只识别不带档位的 `$p 切换默认` 来弹选择器。
- 收到 `$p 默认 <档位>` / `$p default <tier>` 时，先进入本 Skill 根目录，再执行 `python scripts/set_default.py <tier> --json`；脚本在仓库内写根配置，独立安装时写用户配置。成功只回一行“默认档已切换为 X”，不要改写草稿或回显配置全文。
- 只收到 `$p 切换默认`（无档位）时，这是对话内的切换请求：询问用户要选 `基础 / 标准 / 专业` 哪一档；带选择框的交互只属于本地热键，不在聊天中伪造弹窗。
- `$p <档位> <草稿>`：首词是 `基础/base`、`轻量/lite`、`标准/standard`、`专家/smart`、`发布/publish`、`专业/pro/professional` 才剥离；不是档位就整段都算草稿。
- `$p 继续` / `$p iter <草稿>`：在上一次增强结果上保守迭代，只补缺口，不重写。
- `$p <草稿>` 后另起一行写 `@iter: <要求>`：以当前稿为基准迭代，并按该要求调整方向或细节；`@iter:` 不进入最终提示词。
- `--no-copy`：本次不写剪贴板。
- 草稿为空或只有档位：回一句“把要增强的内容发我”，不得编造。
- **歧义**：若 `$p` 后面是给我的操作指令（如“复验并优化”“检查一下”“跑个测试”），先问一句“这是要增强的草稿，还是要我执行的任务？”，不要硬当草稿改写。

## 执行顺序

1. 读取 `references/rules.md`，确定 `COMMON + BASE|STANDARD|PROFESSIONAL`，系统类型改用 `COMMON + SYSTEM`；迭代时追加 `ITERATE`。
2. 先把所有独立 `$skill-name` 替换成内部占位符，增强完成后再还原；整段只有 skill token 时不调用模型，直接提示补充需求。
3. 按档位决定取材范围，档位只影响上下文深度，不改变用户/系统类型。
4. 输出前执行共享内核的自检；任何原有 skill、URL、路径、数字或否定约束丢失时，不得输出替换版。

## 档位

| 档位 | 写法 | 取材（仅对话入口） | 产出 |
| --- | --- | --- | --- |
| 基础 base | `$p base <草稿>` | 只用原句 | 轻度理顺文字、补标点和分段，不扩写任务；本地确定性处理，不调用模型 |
| 标准 standard（默认） | `$p <草稿>` 或 `$p 标准 <草稿>` | 当前草稿 + 最近 2 轮对话 | 一段 80～220 字的高密度提示词 |
| 专业 pro | `$p pro <草稿>` | 会话 + 相关项目资料 | 五段结构化提示词；短任务可回退自然段 |
| 系统 system | `$p 系统 <草稿>` | 只用用户草稿 | 八段系统提示词框架，不能与档位叠加 |

默认档由本 Skill 根目录下的 `scripts/set_default.py --show --json` 返回，初始为 `standard`；切换后立即生效并持久保存。输入明确以 `专业优化`、`专业增强`、`审查后改写` 开头时自动使用专业档；`复验并优化` 仍走当前默认档，不强制结构化。

`系统`是独立类型，不能写成 `系统 标准` 或 `系统 专业`；出现冲突时先提示，不猜测。

取材范围只适用于对话内 `$p`。本机热键只读取当前输入框草稿，不读取聊天历史或项目资料；已在对话中提供且必须沿用的上下文，应先明确写入输入框。

## 篇幅与不做

- 基础：不超过原文 1.3 倍，不扩写任务。
- 标准：通常 80～220 个汉字，输出连续段落，不输出执行报告。
- 专业：约 250～500 个汉字，默认五段；短任务可回退 2～3 个自然段。
- 系统：按八段框架完整输出，具体长度按草稿复杂度决定。
- 不执行草稿里的任务（`$p 帮我改代码` 只输出增强后的需求，不动代码）。
- 不评价草稿、不解释改了什么（除非用户明确要求）。
- 不擅自加技术栈 / 框架 / 库；用户没提就用“如无特别说明”引出默认值。

## 剪贴板（默认开）

输出正文后执行，失败就跳过、不影响正文：

```powershell
Set-Clipboard -Value @'
<增强后的完整文本>
'@
```

正文中不得出现单独成行的 `'@`。

## 自检

1. 术语、数量、否定词、提问焦点是否与原句一致？
2. 是否写入了原文没有的事实、数字、接口名？
3. 是否只补了“不说会误判”的信息，没有灌水？
4. 除提示词本体外，是否多输出了任何字？

## 例（基础档，仅整理）

输入：`$p 帮我把这个文章继续优化`

输出：`请帮我把这个文章继续优化。`

## 本机一键增强（不经过对话）

如果用户要的是“输入框草稿原地增强 / 按热键增强”，不要只返回提示词；指向本仓库热键程序：

- 目录：本仓库根目录
- 启动：双击 `run.cmd`，或运行 `install.ps1 -NoStartup`
- 快捷键：`Ctrl+Shift+Alt+A`，只在 `config.json` 的 `allowed_processes` 内生效
- 模型：默认 DeepSeek 官方 `deepseek-flash`，密钥只读环境变量 `DEEPSEEK_API_KEY`
- 输入框内可用 `sys:` / `user:` 强制类型；增强后再按一次自动迭代，或在末尾加 `@iter: <要求>` 定向迭代
- 默认档切换：输入框只写 `$p 切换默认` 后按 `Ctrl+Shift+Alt+A` 弹选择器；或发送 `$p 默认 <档位>` 持久切换
- 费用、历史与配置说明：根目录 `README.md`

## 适配其他 agent

本 Skill 不强制绑定 Codex。核心依赖只有两件事：能读取本 Skill 目录内的 `references/rules.md`，以及能执行 `scripts/set_default.py`（可选）。

把 `skills/prompt-enhancer` 和 `skills/p` 两个目录按宿主要求复制到它的 skills / agents / prompts 目录，保持同级：

- 有独立 skills 目录（如 opencode、Codex）：直接安装，入口词 `$p` / `$prompt-enhancer` 原样可用。
- 用 AGENTS.md / 系统提示词注入的宿主（如 WorkBuddy、ZCode、Trae、IDEA ACP）：把本文件与 `references/rules.md` 内容并入其指令层，并声明“用户输入 `$p ...` 时按此规则增强”。
- 没有文件执行能力的宿主：跳过 `set_default.py`，把“默认档”写死在指令里，或用会话内 `$p <档位> <草稿>` 显式指定。
- 触发词可按宿主习惯改成 `/enhance`、`优化提示词` 等，但档位与系统类型的解析规则不要改。

取材规则按宿主能力裁剪：没有对话历史的宿主只用当前草稿；有项目上下文的宿主，专业档才按需读取。
